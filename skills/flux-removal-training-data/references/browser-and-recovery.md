# Chrome 网站操作与断联恢复

## 环境

在另一台Windows、非Codex设备上默认使用 **Google Chrome**；用户明确授权Edge、内置浏览器或双浏览器时按其指示。优先连接用户正常会话；安装或扩大权限按当前agent规则处理。不复制其他设备的cookies、令牌或身份。技能只规定可观察的操作，不依赖特定自动化库。

打开 https://flux-tools.bfl.ai/precise-editing ，观察页面标题与正文。正常起始页含Upload your own和示例图片。自动验证可等待其正常完成；出现交互验证按当前工具政策处理，必要时让用户手动完成。

## 扩展浏览器连接与文件选择

当用户要求操作其Chrome/Edge时，选择当前连接的`extension`后端，不用内置`iab`代替外部浏览器。每次操作前刷新`agent.browsers.list()`和所选浏览器的`user.openTabs()`，从最新返回对象选择目标并`user.claimTab(对象)`，再读取`tab.playwright.domSnapshot()`。不复用重启前的数字ID或mention；claim提示找不到标签页时只重新列出并claim一次，不据此更换后端。

若环境暴露`mcp__cua_repl.js`，首次或重置后先仅执行`await cua.getState();`并读返回文档；用`cua.listBrowsers()`发现当前连接，再`cua.getBrowser({id:当前id})`取得绑定与API文档。若没有这些工具，说明能力缺失，按当前agent可用的正式浏览器工具处理，不臆造API或手动导入插件缓存作为默认替代。连接修复先只读确认页面，不为测试额外上传、Start over或Generate。

上传使用文件选择事件：先调用`tab.playwright.waitForEvent('filechooser', ...)`并立即挂接错误处理，再点击已观察到的上传按钮，取得chooser后`chooser.setFiles([绝对路径])`。上传后重新读取页面，确认图片进入画布并完成解码，再填写提示词。Windows路径可使用正斜杠，避免JavaScript反斜杠转义损坏路径。

## 控件与数据流说明

- Upload your own：文件选择器上传工作图；先监听文件选择再点击，按本机绝对路径选文件，观察图片进入画布。
- Add region：矩形局部指令，可移动、调大小；区域有Done、Delete和单独参考图入口。区域不是精确像素mask，不能替代训练对象mask。
- Hide regions：显示/隐藏区域标记，无区域时可能禁用。
- 主prompt框：全图编辑要求；局部指令可并用。对象本体被框住不表示阴影一定被覆盖，必须检查生成结果。
- Add reference：整体参考图。默认不添加无关参考图。
- Model：历史实测有FLUX 3 Large / Klein，当前以实际菜单为准；本尺寸表仅验证Large。
- View prompt：Summary和Model prompt预览，可能有复制入口。
- Generate / Cancel：提交或取消生成。提交前把任务标记submitting；看到Generating后标记generating。
- Orig / V1等版本按钮、Compare：查看原图、生成版本及对比；下载前核对当前版本。
- 读取版本前先明确选择V1等目标版本，再在下一次观察中核对画布已切换并加载完成；不要切换后立即读取旧画布。无显著变化或仍含原始主体的候选不能直接作为完成结果，保留原文件并进入待审或累计次数内重试。关闭结果页前完成文件解码与内容核验。
- Download：保存当前版本；优先网站下载。工具允许时，可导出当前可见图片的原始data URL或已观察资源。不能请求隐藏内部接口、提取隐藏应用状态或用截图替代原始输出。
- 下载事件监听超时不等于生成失败：先检查浏览器实际下载文件，完整解码、核对尺寸、视觉身份及SHA-256，再决定是否仍需保存。不得因下载监听失败重新Generate；不要关闭尚未保存的结果页。默认下载位置若不在用户数据盘，核验后迁移到指定数据盘并记录来源。
- Start over、返回起始页：可能丢失编辑历史。先保存候选文件和任务状态，离开前阅读警告。
- 缩放±与Fit：仅影响视图，不用于判定图像像素宽高。

## 断联分类

用户观察到频繁操作后出现 **“Failed to verify your browser / Code 10”**。这是浏览器验证失败的可见表现；**不能仅凭此判定为限流、IP封禁或请求次数导致**。

区分：浏览器工具连接中断；网站网络加载失败；浏览器验证失败；页面明确提示限流/Retry-After；生成失败；生成状态未知。将实际文字、时间、截图文件路径和最近任务记录下来，不把这些故障都称作“断联”。

## 默认节流与恢复步骤（运维默认值，并非官方限额）

1. 默认串行；用户明确指定双浏览器并行时每浏览器最多一个在途请求。全局相邻提交至少15秒，上传后亦给页面至少15秒完成解码；这些是运维默认值，不是官方限额。出现错误后退避，不用多开页增加请求压力。
2. 一旦出现Code 10、验证失败、重复连接错误或明确限流，停止所有新上传/生成，落盘当前任务和队列。不要连续刷新、自动重复Generate或切换大量标签页。
3. 若仅agent与Chrome连接断开：重新连接**同一Chrome会话**，列出现有标签页、查看现有页面；只重连一次，不直接重开网站或重新提交任务。
4. 若网站无法进入：保留原结果标签页；优先使用原页面检查，不关闭可能含未保存结果的标签页。明确Retry-After时等待至少其指定时长；否则Code 10/网络失败的恢复检查间隔依次为60秒、180秒、600秒，最多三次。长等待期间保持任务落盘，工具允许时分段等待并向用户说明进度。
5. 每次恢复只做一次导航/必要刷新并观察，不循环轰炸页面。正常可访问后，先检查Orig/V1版本、生成状态和已保存文件。
6. 已生成且可查看：下载并校验后续跑。仍在Generating：继续观察。请求是否提交不明且无可恢复状态：标记`unknown_submission`，交由用户核对后再决定是否重交，不能自动当失败重试。
7. 三次恢复仍失败：设为`blocked_browser_verification`或对应原因并停止自动访问，给出Chrome中的手动检查步骤及续跑任务。用户手动恢复后先处理在途任务，再以串行节奏继续。

不要自动清除浏览器站点数据、登出、换代理/IP、关闭安全保护、修改指纹、切换隐身或试图绕过验证。若需要处理Chrome更新、扩展冲突或网络设置，先保留任务证据，再由用户选择处理；不得把这些猜测写成已查明原因。

## 任务检查点

### URL无法确认导致的工具安全中止

“无法足够确定Windows当前浏览器URL”属于工具层安全中止报告，区别于FLUX页面Code 10、网站限流和普通CDP超时。仅凭该报告不能判断模型能力或站点原因。

浏览器操作开始前优先使用正常连接的专用浏览器工具，读取当前标签URL和页面，不把“使用本机Chrome”解释为必须走原生桌面点击。若已经明确安全中止，则本轮不再发送浏览器输入，也不转Edge、内置浏览器、低层自动化或截图坐标绕过。保留已有文件和未知请求状态，本地数据检查可继续。

请用户手动打开目标HTTPS页面并正常完成登录/验证；下一轮仅在工具允许时先只读发现、核验当前标签与URL，成功后再恢复上传。用户口头确认URL不能替代工具验证。仍中止则交用户手工完成网页部分，不承诺换模型或改prompt即可解除。

每条任务用独立JSON原子落盘（临时文件写完后rename），至少记录：task_id、source_group、instance_ids、category、输入/标注路径与哈希、resize尺寸、prompt、model、attempt、stage、updated_at、输出路径、last_error。浏览器页面地址可记录，鉴权令牌/cookies不得进入技能包或共享manifest。

阶段：prepared → submitting → generating → downloaded → needs_shadow_review → composited → pending_review → accepted；异常可为generation_failed、unknown_submission、blocked_browser_verification。

只有内容和哈希匹配的已完成阶段可以跳过。回贴/导出属于本地步骤，网页断联不影响已有素材的处理。恢复后重新核验文件存在、解码尺寸与状态，不仅相信旧标签页ID。

自动验证刚结束时，工具可能短暂报告DOM/CDP读取超时，而页面实际已到上传界面。此时先对同一标签页取一次截图，再按新DOM观察恢复；不立刻刷新、换浏览器或重交。若连接本身确已断开，使用工具允许的同一会话恢复，不继续沿用失效句柄。出现明确工具安全中止时停止该操作，不换接口绕过。
